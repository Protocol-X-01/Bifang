without making inference or deployment requests. Its chat-completion request
includes a free-form `extra_body`, but no explicit KV dtype/quantization field.

## Multi-model implementation acceptance

The local router now supports explicit pinned and opt-in automatic selection.
Pinned mode remains the default and preserves NIM/custom deployments.
`BIFANG_ROUTING_MODE=auto` enables Token Factory task-role selection; the desktop
also offers per-request selection without mutating shared configuration.
Role overrides use `BIFANG_FAST_MODEL`, `BIFANG_BALANCED_MODEL` and
`BIFANG_REASONING_MODEL`. Automatic and explicit Token Factory selections must
appear in a strict live catalog (cached for five minutes); a failed catalog or
absent model raises a visible error, not fallback inference. The desktop lists
live Nemotron identifiers and retains the configured deployment separately.
Receipts distinguish the requested identifier from the server-reported model,
which remains null if absent. History retains these receipts.

The bounded October 23 live smoke used explicit task types and a synthetic
read-only fixture: all three default roles returned their requested model IDs
and made one file read with two model requests each. Super and Ultra passed
the exact final-answer criterion; Nano did not. That is a failed quality gate,
not an all-model success. See the [sanitized report](evidence/model-routing-live.json).
Do not remove it from the report or claim coding
accuracy, adaptive-classification quality, throughput or cost savings from it.
The first run lost its report to a local report-writer error; a corrected,
bounded second run produced the recorded result. No GPU rental occurred.

Candidates for fast, balanced and deep-review roles must come from the actual
Token Factory catalog and be tested for tool compatibility. Keep provider
credentials separate from model-vendor names. Show chosen/actual model and
provider per request; do not present an unverified fallback list as live
availability. Do not implement repeated blind retries or hidden fan-out calls.
Routing quality and cost savings need held-out task evidence, not tier labels.
